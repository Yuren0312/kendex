# Overseer host

The `scripts/overseer-host` command selects the runtime the OVERSEER's own session runs in from `ORCH_OVERSEER_HOST`. `resolve` prints `tmux` when the setting is empty or `tmux`, which is the included provider `scripts/overseer-host-tmux`. Any other value is an executable script path speaking the protocol below. The setting chooses once per session and the session record keeps the runtime. Today both launchers refuse any runtime but `tmux` as `runtime-unsupported` before anything opens, through one rule in `lib/overseer-launch.sh`, because each verifies the new session's account through its tmux pane; a provider for another runtime needs the account read in this protocol first. `oversee launch`, `oversee-succeed` and Jarvis call `scripts/controller-session` for the controller lifetime. The owner uses `create` to acquire a waiting runner. It confirms the exact predecessor ended before releasing native startup. Native identity, the selected account, any required kickoff completion and the brief receipt precede Running and controller mail. `inspect`, through `lib/overseer-launch.sh`’s `ol_session_inspect`, serves the launch’s live-controller check and the watch’s pane observation. Account choice, marks and recovery limits stay with those callers. The adapter does four primitive things to one exact session.

## Provider protocol

A `SESSION` is the runtime's own identifier of one session: on tmux a pane id, `%N`.

| Verb | Arguments | Result |
|---|---|---|
| `create` | `--cwd DIR (--after SESSION \| --session NAME) [--name NAME] --line COMMAND` | Open a session running `COMMAND` from `DIR`, at the base index of the session `--after` names or of the runtime session `--session` names, and print one line, `session=SESSION window=WINDOW server=SERVER`, before the harness has drawn anything. A create that opened a session and could not start the command in it closes that session again and fails. HUP, INT and TERM do not interrupt a create between opening the session and printing its line, so a caller's close-out can read the session off it. |
| `inspect` | `--session SESSION [--launch] [--server PID --server-start EPOCH [--server-socket PATH]]` | Print one keyed line, `session= window= server= state=STATE`, then the session's snapshot. Without `--launch`, `STATE` is `lib/lane-state.sh`'s word for the session, which that shared judge defines, with `wall_kind=auth` or `wall_kind=usage` on a walled reading and no wall kind on any other state. The watch consumes `auth` for first-pass login recovery. `cause=` names each scan the judge could not run, comma-separated, and `probe=` the child probe's exit status where one is `process-probe`. `--launch` is the first-turn reading of a session opened seconds ago: `working` where a turn is in flight anywhere on the screen, `asking` where the folder-trust dialog holds the harness, `idle` otherwise; under `asking` the snapshot is the line that holds it. With a recorded socket, tmux verifies the recorded server pid and start before reading the pane and includes `server_start=` in its answer. A stopped recorded server, including a missing or refused recorded socket, or a different start is `state=gone`. A saved server identity without a socket still binds the read to that server; if it runs but cannot be judged from the caller socket, inspection refuses `session-unreadable`. A failed process or pane-list read also refuses and includes its cause. A session the runtime no longer lists is `state=gone` with no snapshot, at exit 0, `window` and `server` then `none`; a session that stops being listed during the read answers the same. |
| `deliver` | `--session SESSION`, the block on stdin | Put the block where the session's harness reads it and print `deliver=ROUTE session=SESSION`. The block is consumed whole whatever the outcome. A session the runtime no longer lists refuses at exit `4` under `session-gone`. |
| `stop` | `--session SESSION [--successor SESSION]` | End the harness, close the session and print `stopped session=SESSION window=WINDOW`. With `--successor`, the successor keeps its base index and becomes the selected window. Without it, undo an uncommitted insertion and restore the displaced windows. A session the runtime no longer lists prints `window=none` at exit 0. |

- A refusal is one keyed line on stderr, `<provider>: <key> <field>=<value>`, with the runtime's own words under it, at exit 1. A usage error exits 2.
- The dispatcher passes all provider bytes and exit codes unchanged. It refuses a verb outside the four as `verb-invalid` at exit 2 and a provider path that is not executable as `host-unavailable` at exit 2.
- A caller decides on `state=` and relays the snapshot under its own refusal as detail.

### Recorded harness observation

The tmux provider adds `harness_state=running|stopped|unknown` beside `state=`. Fleet readers use this fact for the recorded harness process. The pane's `state=` keeps its existing meaning.

- `running`: the saved PID is alive with the saved process start. A saved exit from an earlier run cannot override this identity.
- `stopped`: the saved identity has ended and the pane observation is `exited`, which requires shells only. A missing process, zombie or different process start ends the saved identity. A bound `exit.run` supplies the completed identity after active fields clear.
- `unknown`: no bound identity exists, a read fails, or an ended identity's pane does not read `exited`. A program started by a person after the harness exits therefore reads unknown. Pane presence never proves a running harness.

`harness_cause=` names the reason for `unknown`: `record-unreadable`, `server-start-unreadable`, `record-unbound`, `identity-unrecorded`, `identity-invalid`, `state-read-failed`, `start-read-failed`, `process-probe-failed`, `pane-not-exited` or `pane-gone`. Other providers that do not record a process identity answer unknown.


## The tmux provider

`overseer-host-tmux --help` owns its options. Without `inspect --server-socket`, it reaches the tmux server the caller's tmux calls reach: the one `$TMUX` names, or the person's own at the socket tmux derives from their uid when `$TMUX` is unset (`scripts/lib/tmux-server.sh`).

| Verb | tmux calls |
|---|---|
| `create` | `new-window -d -b` before the session's configured base index, for a predecessor's session or a named session, `-n NAME -c DIR`; then `COMMAND` and `Enter` through `lib/pane-write.sh`'s `pane_write`, which types only into a pane at its shell. The new window's `@orch_overseer_displaced` option holds the displaced window ids in index order. Failed pane-write cleanup restores them before closing the new window. `server=` is the tmux server pid, the first half of the `<server pid> <pane id>` key every reader of the session record compares. |
| `inspect` | `capture-pane -pJ` is the snapshot. The settled reading feeds it, the pane's pid and its foreground command to `lane_state`; `--launch` reads it whole through `pane_working` and `pane_trust_dialog`. |
| `deliver` | Nothing forwards the block: the harness in the pane reads the watch log inside its own turn. The verb proves the pane is live. `ROUTE` is `watch-log`. |
| `stop` | Without a successor, swap the inserted window through its recorded displaced windows, then `kill-window` in one client call. This restores their indexes and preserves gaps when renumbering is off. With a successor, `kill-window`, clear the successor's displacement option, and `select-window` in one client call. The successor keeps the base index create gave it. |

## The session record

`scripts/controller-session` owns the oversee state’s `.overseer` object. Jarvis’s public command delegates to this operation and keeps its response format. Native callbacks use the existing `JARVIS_RECORD` and `JARVIS_GENERATION` names; the record path now names the resolved oversee state. All record mutations take that state file’s lock.

The root identity names only the confirmed controller. `.lifecycle` holds request policy, the candidate’s native binding and the transfer. It can exist before a controller has registered, with no root pane or native identity. Its request generation cancels obsolete workers; root `generation` counts controller instances and stays unchanged on repeated registration. Root `pending` is the chosen successor command. Lifecycle `pending` is its native confirmation and brief receipt. These are separate contracts.

A transfer saves its available handoff and exact predecessor, acquires a waiting runner, marks `retiring`, confirms predecessor retirement, then releases native startup. Retirement, Stop and failed-candidate cleanup run outside the state lock so native exit and caller signal handlers can complete their own writes. The worker rechecks its request under lock before publishing retirement. Start keeps retirement in progress while its worker lives; a concurrent Stop can cancel it and preserve Off. Refused retries retain their owned waiting panes and predecessor chain. The root controller, including its recorded exit, selects the caller's predecessor rather than a failed waiting pane. Native callbacks bind the same unretired chain. Retirement and Stop end that chain before releasing native work; candidate cleanup ends only the candidate, including a Jarvis Start replacement. Confirmed retirement releases predecessor authority; saved handoff and conversation history remain. Confirmed Stop releases its process and predecessor facts. A saved waiting pane can precede its tmux generation mark, but native startup still requires its exact generation binding. The waiting runner has no controller mail permission. The root has no active identity between confirmed retirement and successful native startup. Mail queues during that interval. Before-retirement failure retains the predecessor; lifecycle `request_failure` records the failed request generation and result separately, so a launch returns failure while the retained controller can still report Running. After-retirement failure retains failed recovery input and never restores the predecessor. After retirement, an unfinished transfer whose worker has ended reports failed recovery. Live succession requires its handoff file. Dead and walled recovery retain their caller's existing recovery contract when the snapshot is missing; an existing snapshot is still saved before retirement.

An orch worker starts through the existing job runner, outside its caller’s descendant tree and watch service. Its PID and start acknowledgement are saved under the state lock before it can acquire a terminal. Jarvis’s desktop worker retains its owned child route. Both use the same lifecycle operations and native confirmation. Caller fleet/watch policy crosses the service boundary; native startup separately scrubs inherited harness identity and selects its account.

`oversee register` binds a hand-opened session through the same owner after its pane-owned SessionStart row confirms the native identity. During confirmation it reports `registration-pending` at exit 1 and publishes no controller; retry after SessionStart. A managed launch remains pending until its worker completes the Start receipt. `registered` names a completed active binding. Repeated registration retains that session’s known native identity. A different session inherits no predecessor account or native identity. A watch can refresh only the controller it already names.

`overseer-run` binds a managed candidate’s native PID and start to lifecycle `native_process` before executing its command; failure refuses native startup. The pane resource remains separate and supplies no native PID. Its exact exit writes `native_exit` on the matching lifecycle controller or saved predecessor and, when the root names that run, the existing root `exit.run`. Native events and exits bind to `pending.generation`, which survives a failed replacement’s newer request generation. The watch can then confirm native death beside the surviving pane shell. Existing direct callers retain their advisory record contract. An existing orch root record without a lifecycle member retains its completed native run when read through the shared status view. Neither pending native binding nor exit grants controller mail permission.

The caller resolves the fleet record before registration, launch or recovery. The observed session `cwd` is identity and startup data; it never selects another record. Registration retains the SessionStart rows path it observed, even when the native row reports an earlier working directory. The record is local to the canonical home. A copied handoff does not grant a live identity. A different canonical home refuses reuse. If the former XDG Jarvis record exists, the owner refuses launch and registration. `controller-session retire-legacy --home HOME` confirms the recorded worker and controller identities have ended before moving Off and boot policy to orch and removing that retired file. A live old worker refuses retirement; wait for its bounded Start, Stop or succession command to settle, then retry. Retirement rechecks the old request identity after teardown; a concurrent old Start leaves its authority in place. A failed stop leaves the old file in place. Deleting a live record by hand never establishes retirement.
